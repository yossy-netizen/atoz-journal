# PitchTrace やさしい解説 ― 打ち込みに「人が弾いた感じ」を足す道具

対象読者: 音楽制作の専門知識がない人、スタッフ、はじめて触る人。
むずかしい言葉は [`BACKGROUND.md`（周辺知識）](BACKGROUND.md) に説明があります。
操作の細かいことは [`MANUAL.md`（詳細マニュアル）](MANUAL.md) にあります。

---

## 1. なにを解決する道具？

パソコンで音楽を作るとき、メロディを「打ち込み」で作ることがあります。
ピアノロール（マス目の画面）に音を置いていく、あれです。

でも、バイオリンやチェロ、サックスの音を打ち込みで作ると、どこか**機械っぽく**聞こえます。
なぜでしょう？

答えは「**音の高さが、まっすぐすぎるから**」です。

本物の奏者が弾くと、音の高さ（ピッチ）はこんなふうに動いています。

```
本物の演奏の音の高さ（イメージ）

高い ┤        ╭╮╭╮╭╮╭╮
     │   ╭────╯╰╯╰╯╰╯╰──╮
     │  ╱                ╰╮       ← 音の終わりで少し下がる
     │ ╱  ↑しゃくり上げて入る       ↑ここで ゆらゆら（ビブラート）
低い ┤╱
     └──────────────────────── 時間

打ち込みの音の高さ

高い ┤ ────────────────────
     │
低い ┤
     └──────────────────────── 時間   ← 定規で引いた線みたい
```

- 音の出だしに、ほんの少し下から「しゃくり上げる」
- 前の音から次の音へ「なめらかに滑る」
- 長い音では「ゆらゆら揺れる」（ビブラート）
- 音の終わりに「ちょっと落ちる」

こういう「動き」が、生演奏らしさの正体のひとつです。
**PitchTrace は、この「動き」を打ち込みに自動で足す道具**です。

## 2. たとえ話: 「何を弾くか」と「どう弾くか」

楽譜（や打ち込みの MIDI）に書いてあるのは「**何を弾くか**」です。
ド、レ、ミ、どのくらいの長さで。

でも演奏には「**どう弾くか**」があります。
同じ「ド」でも、そっと入るのか、しゃくり上げるのか、震わせるのか。

PitchTrace は「何を弾くか」（MIDI）を受け取って、「どう弾くか」（音の高さの動き）を
書き足して返します。楽譜が演奏になるイメージです。

「どう弾くか」の元ネタは 2 つあります。

1. **楽器ごとの「クセの辞書」**（プロファイル）
   「バイオリンのクラシック奏者は、ビブラートは 1 秒に 6 回くらい、こんな深さで、
   音の出だしから 0.15 秒くらいしてから始める…」という統計です。最初から 5 種類入っています
2. **本物の録音**（参照演奏）
   チェロ奏者の録音を読み込ませると、その人の「動き」を取り出して、別のメロディに移せます。
   「この人っぽく弾いて」ができます

---

## 3. 7 つの「動き」

PitchTrace は音の高さの動きを 7 つに分けて考えます。全部に名前が付いています。

| 名前 | ひとことで | 身近なたとえ |
|---|---|---|
| イントネーション | その音全体が、ほんの少し高め／低めになること | 歌う人が「導音」（次にドに行くシ）を少し高めに歌うのと同じ |
| トランジション（ポルタメント） | 前の音から次の音へ、なめらかに滑ること | 「ド〜〜レ」と指を滑らせる感じ |
| アタック | 音の出だしで、下から（上から）目標の高さに入ること | 「うぃーん」の「う」 |
| ビブラート | 音を規則正しく揺らすこと | 歌手が長く伸ばすときの「あぁぁぁ〜」 |
| ドリフト | ゆっくり、不規則にふらつくこと | 呼吸や弓の力加減で、じわっと変わる |
| リリース | 音の終わりに、少し下がったり抜けたりすること | 息が減って音が下がる |
| ジッタ | ごく小さな、ざらざらした揺れ | 手ぶれ |

音の高さのほかに、**音量の動き**（ふくらんだりしぼんだり）と、**タイミングのずれ**
（ほんの少し早く／遅く入る）も足します。

## 4. 使ってみる（3 ステップ）

はじめて使うときは、Mac のターミナルで次を打ちます（1 行ずつ、Enter で実行）。

```bash
cd atoz-journal/pitch-trace
bash scripts/setup_mac.sh --logic
source .venv/bin/activate
```

1 つ目の行は「PitchTrace の入っているフォルダに移動する」、2 つ目は「準備をぜんぶやる」、
3 つ目は「これから使うよ」という合図です。2 つ目は数分かかります。

最後に**環境しんだん**（doctor）が自動で走り、こんな一覧が出ます。

```
[OK  ] Python のバージョン: 3.12.4
[OK  ] pitchtrace 本体: 0.4.0
[注意] librosa（pYIN 検出器）: 未インストール
```

- `OK` … 大丈夫
- `注意` … 無くても基本の使い方はできる。必要になったら直す
- `失敗` … ここを直さないと動かない。画面の下に直し方が出ます

`失敗` が 1 つも無ければ準備完了です。あとから調べ直したいときは `pitchtrace doctor` と打ちます。
誰かに相談するときは `pitchtrace doctor --json doctor.json` として、できたファイルの中身を
見せてください。それだけで「何が足りないか」が相手に伝わります。

### ステップ 0: 音程の物差しを合わせる（Logic などの DAW を使う人）

**ここを飛ばすと、あとの全部がズレます。** 大事なので先にやります。

PitchTrace は音の高さの動きを「ピッチベンド」という仕組みで書きます。ピッチベンドには
**ベンドレンジ**という設定があって、これは「目いっぱい曲げたら何半音ぶん動くか」という意味です。
PitchTrace は「12 半音（1 オクターブ）」で書きます。ところが音源（音を鳴らす側）は
「2 半音」になっていることが多い。物差しの目盛りが違う状態です。そのままだと、
ほんの少し揺らすつもりが、とんでもない音痴になります。

合っているかどうかは、耳で確かめられます。`logic_start/01_bendcheck.mid` を DAW に読み込んで
再生してください。**同じ高さに聞こえるはずの音のペア**が入っています。

| 順番 | 鳴るもの | 正しいときは |
|---|---|---|
| 1 番目 | 低いドと高いド | この 2 つの高さを覚える |
| 2 番目 | 曲げて上げた音 → 高いド | **同じ高さ**に聞こえる |
| 3 番目 | 曲げて下げた音 → 低いド | **同じ高さ**に聞こえる |
| 4 番目 | ゆっくり上がる音 | なめらかで、階段状にならない |

2 番目が低く聞こえたら、音源のベンドレンジが小さすぎます。音源の設定画面で `Bend` とか
`Pitch Bend Range` と書かれた数字を探して **12** にしてください。同じ高さに聞こえたら合格です。

Logic での具体的な場所は [`MAC_SETUP.md`](MAC_SETUP.md) の「Logic Pro で使う」に書いてあります。

### ステップ 1: 聴き比べてみる

`demo_out/demo_static.wav`（まっすぐな音）と `demo_out/demo_violin_classical.wav`
（動きを足した音）を再生して、違いを聴いてください。音自体は簡単なシンセなので
きれいではありませんが、「動き」の違いは分かります。

### ステップ 2: 自分のメロディに使う

DAW（音楽ソフト）でメロディを MIDI ファイルに書き出して、次を打ちます。

```bash
pitchtrace render メロディ.mid メロディ_traced.mid --profile violin_classical
```

`メロディ_traced.mid` を DAW に読み込むと、ピッチベンド（音の高さの動き）と
CC11（音量の動き）が付いています。音源の「ベンドレンジ」が **12** になっていることを
確かめてください（ステップ 0）。

ちゃんと書き込まれたか目で見たいときは、DAW でそのデータを開いて「ピッチベンド」の
表示に切り替えます。音符ごとにくねくねした線が描かれていれば成功です。

楽器を変えるなら `--profile` を変えます。

| 書き方 | 楽器 |
|---|---|
| `--profile violin_classical` | バイオリン（クラシック） |
| `--profile cello_classical` | チェロ（クラシック） |
| `--profile oboe_classical` | オーボエ |
| `--profile alto_sax_classical` | アルトサックス（クラシック） |
| `--profile alto_sax_jazz` | アルトサックス（ジャズ） |

「もう少し控えめに」なら `--amount 0.6`、「ビブラートだけ半分に」なら `--amount-vibrato 0.5`、
「違う振り方で」なら `--seed 2` `--seed 3`… と変えて振り直せます。

### ステップ 3: 本物の録音から「クセ」を取り出す（上級）

チェロの録音（伴奏なし、1 本だけ、WAV ファイル）があるなら:

```bash
pitchtrace analyze チェロ録音.wav --igf チェロ.igf.json --instrument cello
pitchtrace transfer チェロ.igf.json メロディ.mid メロディ_その人風.mid --mapping context
```

1 行目で録音から「動き」を取り出して保存し、2 行目でメロディに移します。

## 5. 本当に良くなった？ ― 思い込みをなくす聴き方

「動きを足したから自然になった気がする」は、思い込みのこともあります。
そこで PitchTrace には**目隠しテスト**の機能があります。

```bash
pitchtrace demo out --profile cello_classical --blind
```

`out` フォルダに `blind_X.wav` `blind_Y.wav` `blind_Z.wav` ができます。
中身は「まっすぐ」「ただランダムに揺らしたもの」「PitchTrace」の 3 つですが、
**どれがどれかは分かりません**。聴いて一番自然だと思うものを決めてから、
`blind_answer.json` を開いて答え合わせをしてください。

「ただランダムに揺らしたもの」より良くなければ、この道具の意味がありません。
この比べ方が、開発の方針を決めるいちばん大事な物差しです。

## 6. よくある質問

**Q. 音源は何でもいい？**
だいたい大丈夫ですが、ビブラートが最初から録音に入っている音源（Kontakt 系に多い）だと、
ビブラートが二重にかかります。音源側のビブラートを切るか、`--vibrato-lane cc` を付けてください。
「物理モデル」タイプの音源（SWAM など）は相性が良いです。

**Q. 音程が全体に変？**
ほぼ「ベンドレンジ」が合っていません。音源側を 12 にするか、`--bend-range` を音源に合わせてください。

**Q. 和音でも使える？**
いいえ。バイオリン、チェロ、オーボエ、サックスのような「1 度に 1 音」の楽器専用です。

**Q. リアルタイムでも使える？**
使えます。`pitchtrace live --profile alto_sax_jazz` で「PitchTrace In / Out」という
仮想の MIDI 端子ができるので、DAW からそこへ送って、戻ってきたものを音源で鳴らします。
つなぎ方は [`MAC_SETUP.md`](MAC_SETUP.md)。

**Q. 出来上がりが気に入らない**
`--seed` を変える（振り直し）、`--amount` を下げる（控えめ）、成分ごとに `--amount-〇〇` で調整、
`--profile` を変える、の順に試してください。

**Q. 「プロファイルの数値は目安」って書いてあるけど？**
最初から入っている 5 つのプロファイルは、文献と経験則で手で決めた値です。
本物の録音を `analyze` にかけると、その録音の実測値で置き換えられます。

## 7. ミニ用語集

| 言葉 | 意味 |
|---|---|
| MIDI | 「どの音を、いつ、どのくらいの強さで」を書いたデータ。楽譜のデジタル版 |
| ピッチ | 音の高さ |
| セント | 音の高さの細かい単位。半音を 100 に分けたもの。5 セントくらいだとほぼ分からない、20 セントで「ずれてる」と気づく |
| ピッチベンド | MIDI で音の高さをなめらかに動かす命令 |
| ベンドレンジ | ピッチベンドを目一杯動かしたときに何半音動くか。送る側と音源側で揃える |
| CC11 | MIDI の「音量の表情」を送る命令の番号（エクスプレッション） |
| プロファイル | 楽器・奏法ごとの「クセの辞書」（数値の入ったファイル） |
| IGF | 録音を解析した結果を保存するファイル形式（Instrument Gesture Format） |
| 転写（transfer） | 録音の「動き」を別のメロディへ移すこと |
| DAW | 音楽制作ソフト（Logic、Cubase、Studio One、Live など） |
| WAV | 音声ファイルの形式のひとつ。圧縮していないので解析に向く |

もっと詳しく知りたくなったら [`BACKGROUND.md`](BACKGROUND.md) へ。

## 8. 困ったときの 3 つの呪文

| 状況 | 打つもの | 何が分かるか |
|---|---|---|
| 動かない、入っているか不安 | `pitchtrace doctor` | 足りないものと、その直し方 |
| 音程が変 | `pitchtrace bendcheck check.mid` | ベンドレンジが合っているか（耳で判定） |
| コマンドが見つからない | `source .venv/bin/activate` | 「これから使う」の合図。毎回必要 |

それでも分からないときは、`pitchtrace doctor --json doctor.json` を実行して、
できた `doctor.json` の中身と、打ったコマンドをそのまま伝えてください。
文章で説明しようとしなくて大丈夫です。
