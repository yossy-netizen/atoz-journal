## 0. 一枚で分かる要約

- **何が変わったか**：10月に `AtoZ_Master/Cross_Reference_Sources/`（以下「共有台帳」）が整い、Claude Code・Cowork・Codex（3台）・Cursor・Grok Bot が **同じフォルダを毎朝読み書きする**仕組みが動き始めた。一方、v2 が事務局と伝令を置くつもりだった **Mac mini の Cowork ローカルタスク（系統A）は 2026-10-06 に保守終了**。v2 の配置はそのままでは成立しない。
- **v3 の考え方**：会議室を共有台帳の中に置き、**各AIが既に持っている朝の確認に「自分宛の軍令状があれば意見書を書く」を1行足す**だけで参加させる。各AIのWeb画面を Chrome で操作する「伝令」は主経路から外し、予備に落とす。
- **新設する自動化は1本**（Claude Code ローカル・系統C `council-daily`）。事務局（蔣琬）と軍師（諸葛亮・龐統・姜維）をこの1本の曜日モードで賄う。参謀（Grok）の10月意見「新しい自動化は増やさない」と、クラウドの使用量上限・承認待ち問題に合わせて痩せさせた。
- **配役の変更**：関羽＝**Codex**（ChatGPT から転生。同じ OpenAI 系で、ファイルを直接読み書きできる）。新顔 **費禕（ひい）＝Cowork**（客席係。生徒DB・問い合わせ・Notta を持つのは Cowork なので「現場の声」を集める）。趙雲（Gemini）と馬良（Perplexity）は **API／CLI 経路**で Phase 2 に参加。張飛（Grok Bot）・馬鈞（Cursor）・蒲元（Codex 子エージェント）は v2 どおり。
- **阿藤さんの関わり方・舞さんの Dropbox・発言の型・状態遷移は v2 のまま**。承認までは議論と提案に留める原則も不変。
- **Phase 1 は 4将で開始**：諸葛亮（Claude Code）・関羽（Codex）・張飛（Grok Bot）・馬鈞（Cursor）。いずれも「ファイルを直接読み書きできる」と台帳で実証済みの AI だけ。

## 6. 阿藤さんの関わり方 ― v2 §6 のまま。入口が3つになる

1. **議題を出す**：`00_議題箱/` にファイルを置く／Claude Chat に「議題：〜」と言い、チャット側 Claude が `Claude_Chat/` 伝言フォルダに `[未対応] YYYY-MM-DD_HHMM_ClaudeChat→AI合議_議題_要約.md` を置く（蔣琬が翌朝拾う）／モーニングブリーフに返信（Cowork が議題箱に転記）。
2. **読む**：金曜のモーニングブリーフ（300字＋要決裁3つ）。詳しくは `02_定期報告/` か Dropbox の `index.html`。
3. **採決する**：`90_採決.md` の雛形に書く（採用／条件付き／差戻し／却下／保留＋各将への一言）。チャット側 Claude に口頭で伝えて伝言フォルダに置かせてもよい。

承認までは議論と提案に留める。承認後の「実行タスク化」は、蔣琬が `40_依頼・待ち事項.md` に依頼票を書くところまで。実行は各担当AIの通常の仕組みで行う。

## 7. 人間の組み込み方 ― v2 §7 のまま。費禕の追加

- 費禕（Cowork）は **データの持ち主として**、問い合わせ収集・生徒マスター・Notta の文字起こしから、議題に関係する声を **個人が特定できない形**（「生徒の声（n件）」「講師Aの意見」）で `05_現場の声.md` に添える。原文を引く場合は社内スタッフの実名のみ。
- 舞さんの投稿（Dropbox `02_ご意見/`）は原文のまま「阿藤舞」名義。取り込みは日曜の council-daily（人間の声モード）。

## 10. 失敗に備える v3

| 事象 | 検知 | 対処 |
|---|---|---|
| Mac mini の Claude Code アプリが止まっている／承認待ちでハング（10/23〜25 に実例） | 05:00 routine-health-check の定点（月：軍令状、金：週次報告）。モーニングブリーフが「今週の報告なし」 | council-daily は Python 中心・承認不要コマンドのみ。止まった週は予備の経路C（クラウド Routine）を阿藤さんが手動起動。翌週 round 据え置きで再発行 |
| 使用量上限（Claude Code 週上限・クラウド USAGE_LIMIT） | 実行ログ／`_alerts/` | council-daily の Claude 使用は金曜（統合）と水曜（副将）だけ。他の曜日は Python のみで完結。上限中は「欠席」で会議を止めない |
| 将の未提出（Codex／Cursor／Grok が朝確認で拾わなかった） | 木曜 05:44 の蔣琬が `absent` を確定し `_alerts/` に書く | 諸葛亮が【推定】で補う。3週続いたら `45_気づき` に起票 |
| Codex の他端末が誤って書く | `_status.json` の `器` フィールド | `74_Codex_複数端末の運用.txt` に「AI合議/ は mac-mini-m4 だけ」を明記。他端末の意見書は無効扱い |
| Drive 同期の遅延・衝突名「(1)」（10月に多発） | 蔣琬が `01_進行中/` に「(1)」付きファイルを見つける | 削除せず改名のみ。内容が同じなら片方を `_dup/` にコピーして記録 |
| Cowork の Drive コネクタで .md 本文が空 | 費禕が `00_軍令状.md` を読めない | 費禕は device_bash（添付フォルダ）経由で読む。無理なら欠席 |
| API 鍵の失効・課金停止（Phase 2） | 火・水モードの例外 | 欠席ファイル。鍵の所在は `20_仕様変更・事情の記録` に（値は書かない） |
| ゴーストフォルダへの書き込み | `AI合議/_LIVE_マーカー.txt` | 無ければ書かずに中断・報告 |
| 舞さん共有が Mac mini に同期されていない | council-daily がフォルダの存在を確認 | `_alerts/`。「ローカルに無い＝存在しない」と結論しない |
| 工房が本番に触る | 馬鈞の人格定義と `.cursor/rules` の作業ディレクトリ固定 | 検証はコピーの上で。違反は大評定で経路見直し |
| 議題が無い週 | 議題箱が空 | 自動起案1件（許可済み）。「休会」と書けば休会 |
| 転生（AIの更新で人格が変わる） | 大評定で採用率・欠席率・温度を集計 | 配置転換案を阿藤さんに提示 |
