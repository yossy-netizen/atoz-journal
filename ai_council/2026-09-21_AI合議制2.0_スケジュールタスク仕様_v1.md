## 1. 共通仕様（全タスク）

### 1-1. 起動時の点検
1. マシン確定は不要（Mac miniローカルタスクはMac miniでしか動かない。クラウドRoutineはDrive MCPで完結）。
2. 会議室のルート：
   - Mac mini：`/Volumes/Cloud_Drive/Google_Drive_My_Drive/AtoZ_Cowork/Documents/AI会議/合議2.0/`（実体パス。`.tmp/` 経由は使わない）
   - クラウド：Google Drive MCP で `AtoZ_Cowork` → `Documents` → `AI会議` → `合議2.0` を **名前で辿る**（IDを直書きしない。`entity not found` は0件と判定せず再解決）
3. ルート直下の `_正規フォルダ_LIVE_マーカー.txt` を確認。無ければ **書かずに中断**し、サマリーに理由を書く。
4. 日本語ファイル名の照合は Python で `unicodedata.normalize('NFC', …)` を通す。grep/find に日本語を渡さない。

### 1-2. 状態ファイル `_status.json`
```json
{
  "id": "2026-09-28_koushi-zouin",
  "title": "講師の増員は必要か",
  "type": "weekly",              // weekly | grand | urgent
  "round": 1,
  "state": "in_progress",        // issued|in_progress|synthesized|reported|approved|approved_with_conditions|returned|rejected|held
  "issued_at": "2026-09-28T05:30:00+09:00",
  "report_due": "2026-10-02T05:30:00+09:00",
  "assignments": {"baryo":"required","choun":"required","chohi":"required","kanu":"required",
                  "hoto":"summoned","kyoi":"none","komei":"required"},
  "responses": {"choun": {"file":"20_趙雲_意見.md","at":"2026-09-30T05:41:00+09:00","status":"done","relay":"chrome_mcp"}},
  "human_voice": {"file":"05_現場の声.md","count":3},
  "decision": null,
  "history": [{"at":"…","by":"council-clerk-agenda-issue","event":"issued"}]
}
```
- 更新は **既存ファイルを開いて上書き**（Python: `open(path,'r+b')` → seek(0) → write → truncate → fsync）。新規作成→置換は禁止（DriveファイルID維持）。
- クラウド側は Drive MCP の `update_file` で同一IDを更新する。

### 1-3. 提出ファイルのヘッダ（全意見書共通）
```
---
議題ID: 2026-09-28_koushi-zouin
ラウンド: 1
発言者: 趙雲（Gemini）
経路: chrome_mcp | api | claude_native
モデル/版: （画面表示または API のモデル名。不明なら "unknown"）
投入プロンプト字数: 2,340
作成: 2026-09-30T05:41+09:00 by council-choun-gemini
---
```

### 1-4. 禁止・守秘
- ファイル削除をしない（`_完了/` へのコピーで処理済みを示す）。
- 契約の具体金額・分配率・個人の連絡先を軍令状にも意見書にも入れない。
- 生徒個人が特定できる記述は「生徒の声（n件）」に均す。
- DriveのフォルダID／ファイルIDをSKILL.md本文に直書きしない。

### 1-5. セッションサマリー
- 置き場：`AtoZ_Cowork/Documents/スケジュールタスク_セッションサマリー/業務系/`
- 命名：`YYYY-MM-DD_Cowork_[english-original-name]_サマリー.md`（同日2回目以降は `…_サマリーv2.md`）
- 内容：対象議題ID・提出ファイル名・relay結果（成功／再試行回数／欠席）・字数・所要時間・警報の有無。

### 1-6. 伝令（Chrome MCP relay）の共通手順
AI軍議運用手順書v1 §3〜§4を手順化したもの。#4・#5・#6・#8 が使う。
1. ペルソナ台帳の「常設会話URL」を開く（Chrome MCP `navigate`）。ログイン画面や別ページに飛んだら `_alerts/YYYY-MM-DD_[persona]_login.md` を書いて欠席処理へ。
2. 入力欄を `triple_click → cmd+a → Delete` でクリア（失敗事例6）。
3. 軍令状本文を投入。日本語は `execCommand('insertText')` ＋ `InputEvent` 発火で入れる（type はIMEで崩れる。v3起動プロンプトの知見）。CDPタイムアウトが出ても、スクリーンショットで入力済みなら進む（失敗事例1）。
4. 送信ボタンを `find` で特定して **明示的に click**（Enterは改行になる。失敗事例2）。
5. 送信後にスクリーンショットで「入力欄が空」「新しい応答が始まった」を確認（失敗事例3）。
6. `wait` を10秒×4〜6回。応答の停止を確認。
7. 応答を **上から順に** 全文取得（DOM経由が望ましい。無理ならスクロール＋スクリーンショット。失敗事例4）。
8. 4見出し（【結論】【根拠】【懸念と対案】【劉備への一言】）の有無を検査。欠けていれば「【〇〇】が抜けています。その見出しだけ答えてください」と1回だけ補充投入（失敗事例5）。
9. 保存。`_status.json` の `responses` を更新。
10. 失敗は各段階で最大2回再試行。それでも駄目なら `NN_[persona]_欠席.md`（理由・スクリーンショット名）を書き、`status: absent` にする。会議は止めない。

### 1-7. 軍令状の組み立て（事務局と伝令が共有）
`00_軍令状.md`（議題共通部分）＋ ペルソナ台帳の「投入プロンプト」（将ごと）＋ 先行提出物の要旨（火曜以降は馬良、水曜以降は趙雲・張飛…を各400字以内に圧縮）＋ 前ラウンドの `90_採決.md` の「その将への返答」＋ `05_現場の声.md`（あれば原文）。
上限：合計6,000字。超える場合は先行提出物の圧縮率を上げる（原文はファイル名で参照させる）。

## 2. 各タスクの仕様

### #1 AI合議_事務局_議題発行（council-clerk-agenda-issue）
- **置き場・時刻**：Mac mini／月 05:30
- **入力**：`00_議題箱/`（未処理＝`_完了/` に同名が無いもの）、`01_進行中/*/_status.json` で `state=returned` のもの、既存レポート（週次アクセス統合レポート・GBP・講師別定着分析・miu-clipsコメント分析・体験申込チェックの最新ファイル）
- **手順**：
  1. LIVEマーカー確認。
  2. 議題候補を集める。優先順：【至急】＞ 差戻し（round+1）＞ 議題箱の新規（古い順）＞ 自動起案（議題が0件のときだけ、最大1件。既存レポートから「先週から変化があり判断が要りそうな点」を1つ。ファイル名に【自動起案】）。上限3件／週。
  3. 議題ごとに `01_進行中/YYYY-MM-DD_スラッグ/` を作る（空フォルダはDriveに反映されないので `_status.json` と同時に作る）。
  4. `00_軍令状.md` を templates から生成：議題文・背景（AtoZ_Masterの該当マスター文書 01/03/10 から関連段落を凝縮）・問い（3〜5問）・担当指定（required/optional/excused）・副将招集の有無・締切。
  5. `90_採決.md` のテンプレを置く。
  6. 議題箱の元ファイルを `00_議題箱/_完了/` にコピー。
  7. 各AIサイト（chatgpt.com／gemini.google.com／grok.com／perplexity.ai）の常設会話URLを順に開き、ログイン状態をスクリーンショットで確認。切れていれば `_alerts/` に警報。
  8. サマリー。
- **出力**：議題フォルダ、軍令状、採決テンプレ、警報（あれば）
- **担当指定の既定**：経営・戦略＝全将／スクール運営＝趙雲・関羽 required、張飛 optional／制作・案件＝馬良・諸葛亮・関羽 required／哲学・発信＝張飛・姜維 required、趙雲 optional／技術・自動化＝趙雲 required、他 optional。議題箱のファイルに「担当：…」と書いてあればそれに従う。
- **休会**：議題箱に「休会」というファイルがあれば発行せず、その旨だけサマリーに残す。

### #2 AI合議_事務局_採決取込（council-clerk-decision-intake）
- **置き場・時刻**：Mac mini／毎日 06:30
- **入力**：`01_進行中/*/90_採決.md`（テンプレから変更があるもの）、`00_議題箱/【至急】*`
- **手順**：
  1. 採決ファイルの「決定：」行を読む。
     - 承認／条件付き承認 → `state` 更新。`40_諸葛亮_統合_C案.md` の「実行した場合のタスク案」を、`今日のタスクリスト_DATA/` に **チャット側Claude向けタスクリスト作成手順の書式** で起票（承認後に初めて実行系へ流す）。議題フォルダを `03_決定済み/` にコピー。
     - 差戻し → `state=returned`。翌週の #1 が round+1 で再発行。
     - 却下／保留 → `04_差戻し・却下/` にコピー。
  2. 「各将への返答」を `99_返答配信.md` の素材として保存（諸葛亮が金曜に整える）。
  3. 【至急】議題があれば、#1 と同じ手順でその場で軍令状を発行し、`type=urgent`、担当は既定（諸葛亮・趙雲・関羽）。伝令タスクは通常の曜日を待たず、次に動く伝令が `type=urgent` を最優先で処理する（各伝令の手順に組み込み）。
  4. サマリー。
- **注意**：採決は阿藤さん以外が書かない。テンプレのままなら未採決として何もしない。

### #3 AI合議_事務局_人間の声取込（council-clerk-human-voice-intake）
- **置き場・時刻**：Mac mini／日 22:00
- **入力**：`05_人間意見箱/`（未処理）、`Other_Services/Notta_Export/` の分類済み会議録（notta-transcript-processor の出力）、`School/` の問い合わせ収集結果（inquiry-mail-collector）、Googleフォーム回答（Phase 2）
- **手順**：
  1. 人間意見箱の各ファイルを、宛先の議題（ファイル冒頭の「議題：」行、無ければ翌週発行分全体）に紐づけ、`05_現場の声.md` に **原文のまま** 追記。発言者は「講師 庄子」「スタッフ（匿名希望）」「元請A社（阿藤さん経由）」の形式。
  2. Notta会議録・問い合わせは要点を抜き、【要約】を付けて追記。生徒は件数と傾向に均す。
  3. 処理済みを `05_人間意見箱/_完了/` にコピー。
  4. サマリー。
