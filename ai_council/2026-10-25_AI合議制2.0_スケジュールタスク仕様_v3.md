## 1. 共通仕様（v2 §1 からの変更点だけ）

### 1-1. 起動時の点検（全参加者）
1. 会議室のルート：共有台帳 `Cross_Reference_Sources/AI合議/`。自分の機械の実体パスは `AI_共有パス管理/パス対応表.md` で確定する（Mac mini：`/Volumes/Cloud_Drive/Google_Drive_My_Drive/AtoZ_Master/Cross_Reference_Sources/AI合議/`）。
2. `AI合議/_LIVE_マーカー.txt` が無ければ書かずに中断。
3. `01_進行中/*/_status.json` を読み、`assignments` に自分の将名があり、`responses` に自分が無く、`state` が issued／in_progress の議題だけを対象にする。
4. 書く直前に `TZ=Asia/Tokyo date` で時刻を実測する。
5. 自分のファイルだけを書く。`_status.json` は自分の `responses[将名]` だけを足す（読み→書き戻しは r+ で同一 inode）。他者の意見書は読むだけ。
6. 日本語ファイル名は NFC 正規化で照合。

### 1-2. `_status.json`（v2 §1-2 に `vessel` を追加）
```json
{
  "id": "2026-11-03_koushi-zouin",
  "title": "講師の増員は必要か",
  "type": "weekly",
  "round": 1,
  "state": "in_progress",
  "issued_at": "2026-11-03T05:44:00+09:00",
  "report_due": "2026-11-07T05:44:00+09:00",
  "assignments": {"baryo":"none","choun":"none","chohi":"required","kanu":"required",
                  "bakin":"none","hoto":"none","kyoi":"none","hii":"none","komei":"required"},
  "responses": {
    "chohi": {"file":"21_張飛_意見.md","at":"2026-11-04T08:12:00+09:00","status":"done",
              "route":"xref_morning_check","vessel":"grok-bot/mac-mini-m4","model":"unknown"}

```
Phase 1 の既定 assignments：`chohi: required, kanu: required, komei: required`、実装議題のみ `bakin: required`。Phase 2 から `baryo`・`choun`・`hii` を required に。

### 1-3. 提出ファイルのヘッダ
設計書 v3 §5 のとおり（`経路`・`器` を追加）。

### 1-4. 禁止・守秘・サマリー
v2 §1-4 のまま。council-daily の実行記録は Claude Code ローカルの通常の仕組み（31_現況・60_健全性）に任せ、Cowork 形式のセッションサマリーは作らない。

### 1-5. 共有台帳への書き込み量
`10_相互記録ログ_YYYY-MM.md` に月（発行）と金（報告）の **2ブロックだけ**（4行の型）。`45` は失敗3週連続のときだけ。`40` には書かない。

## 2. 新設：AI合議_事務局と軍師（council-daily）

- **置き場**：`~/.claude/scheduled-tasks/council-daily/SKILL.md`（Y型）。機械処理は `AtoZ_Claude_Code/code/council/council_clerk.py`（新規）に集約し、SKILL.md は「スクリプトを順に呼ぶ＋起草する」だけにする。
- **時刻**：毎日 05:44 JST（05:00 健全性 → 05:40 月曜 inquiry-leak-check → **05:44** → 06:00 xref-inbox-reader）。
- **推奨モデル**：Haiku（月・火・木・日・土・毎日処理）。水・金の起草ターンだけ Sonnet。設定は 1タスク1モデルなので、**Sonnet で登録し、起草しない日は Claude の出番を最小にする**（Python が全部やり、Claude は結果の1行確認だけ）。
- **承認を出さないために**：settings.json の allow に `Bash(python3 /Volumes/Cloud_Drive/Google_Drive_My_Drive/AtoZ_Claude_Code/code/council/*)`、`Bash(TZ=Asia/Tokyo date*)`、`Read`／`Write`／`Edit` の対象に `AI合議/` と Dropbox ミラーの `阿藤舞共有AI合議/` を登録。ブラウザ・Chrome は使わない。
- **所要**：Python 部分 1〜2分。起草日は 5〜10分。

### 2-1. 毎日モード（曜日モードの前に必ず実行）
1. `_LIVE_マーカー.txt` 確認。Dropbox ミラーの `阿藤舞共有AI合議/` の存在確認（無ければ `_alerts/` に書いて続行）。
2. **採決の取込**：`01_進行中/*/90_採決.md` に「採決：」行が入ったもの、`Claude_Chat/` の `[未対応] …ClaudeChat→AI合議_採決_*.md`、`00_議題箱/` の「採決：」で始まるファイルを探す。見つけたら `_status.json` の `decision` と `state` を更新し、`99_返答配信.md` の雛形（各将への返答欄）を置き、議題フォルダを `03_決定済み/` または `04_差戻し・却下/` にコピー。Claude_Chat の伝言は `[対応済]` に改名（共有台帳の規則）。
3. **【至急】の検知**：議題箱に【至急】があれば即時に軍令状を発行し（`type: urgent`、担当は Phase 1：komei・kanu・chohi）、`10` に1行。`_alerts/` に「急使発行」を置く（Grok Bot と Codex が次の起動で拾う）。
4. **状態の整合**：report_due を過ぎた議題を `_alerts/` に。`(1)` 付きの重複ファイルを検知したら改名のみ。
5. **舞さん共有の更新**：採決・新規発行・週次報告のいずれかが前回更新以降にあれば `index.html` と `01_お知らせ/`・`03_これまでの決定/` を再生成（雛形 `templates/mai_share_index.html`）。
6. 変化が無い日は何も書かない（「実行が無い朝も現状を残す」は Cursor の規則で、合議には適用しない）。

### 2-2. 月曜モード：議題発行
1. `00_議題箱/` を読む（【全軍】は type: grand、2ラウンド）。空なら自動起案（設計書 §3-2）。「休会」があれば休会を `10` に1行書いて終了。
2. 議題フォルダ `01_進行中/YYYY-MM-DD_スラッグ/` を作り、`00_軍令状.md`（雛形 `templates/00_軍令状.md`）、`_status.json`、`90_採決.md` の雛形、空の `05_現場の声.md` を置く。前ラウンドの `90_採決.md` の「各将への返答」があれば軍令状に転記。
3. `05_人間意見箱/` と Dropbox `02_ご意見/` の未取込分を `05_現場の声.md` に原文で追記（日曜モードの取りこぼし分）。
4. 発行済み議題を `00_議題箱/_完了/` にコピー。`10` に発行の1ブロック。舞さん共有の index 更新。

### 2-3. 火曜モード：馬良（Phase 2）
`~/.config/atoz-council/.env` に `PERPLEXITY_API_KEY` があれば、Perplexity API（sonar 系）に馬良の投入プロンプト＋軍令状を渡し、出典 URL 付きで `10_馬良_調査.md` に保存（見出し A〜D）。鍵が無い・失敗したら `10_馬良_欠席.md`（理由）と `responses.baryo.status: absent`。

### 2-4. 水曜モード：趙雲（Phase 2）と副将
1. **趙雲**：`gemini` CLI があれば `gemini -p` に軍令状・人格定義・`10_馬良_調査.md` を渡す。無ければ `GEMINI_API_KEY` で API。結果を `20_趙雲_意見.md`。失敗は欠席。
2. **龐統・姜維**（`assignments` が summoned のときだけ）：Claude が **軍令状と先行提出物（馬良・張飛・趙雲）だけ**を読み、龐統として `25_龐統_反対意見.md`、姜維として `35_姜維_継承視点.md` を書く。諸葛亮の統合（金曜）とは別の実行日にすることで、同じ脳の連投を避ける。

### 2-5. 木曜モード：欠席確定と要旨化
1. 水曜までに提出が無い required の将を `absent` に確定（Codex 関羽は木曜 07:00 なのでまだ待つ）。`_alerts/` に欠席一覧。
2. 提出済みの意見書を各 400字以内に圧縮した `_digest.md` を作る（関羽と諸葛亮が読む。原文はファイル名で参照）。合計 6,000字の上限は v2 §1-7 のまま。

### 2-6. 金曜モード：諸葛亮の統合と週次報告
1. 関羽（木 07:00）の提出を確認。無ければ absent。
2. Claude が諸葛亮として `40_諸葛亮_統合_C案.md`（v2 §5-2 の型。欠席者は【推定】）。
3. `02_定期報告/YYYY-MM-DD_AI合議_週次報告.md`（雛形 `templates/週次報告.md`）と `_latest_brief.md`（300字＋要決裁3つ＋採決の書き方1行）を **既存ファイルを開いて書き戻す**。
4. `_status.json` を reported。`10` に報告の1ブロック。舞さん共有の index と `01_お知らせ/` を更新。

### 2-7. 日曜モード：人間の声
`05_人間意見箱/` と Dropbox `02_ご意見/` の未取込分を、次の月曜に発行予定の議題（議題箱の先頭）に紐付けられるよう `05_人間意見箱/_取込待ち.md` にまとめる。取り込んだ Dropbox のファイルは `02_ご意見/_受領済み/` にコピー。

### 2-8. 第1土曜モード：大評定（四半期・Phase 3）
直近四半期の `03_決定済み/`・`04_差戻し・却下/` から採用率・欠席率・ラウンド数を集計し、`07_大評定/YYYY-Qn_大評定.md` に配置転換案とペルソナ台帳の改訂案を書く。改訂は阿藤さん承認後。

### 2-9. 失敗時
各モードは独立。1つが失敗しても次へ進む。例外はすべて `_alerts/YYYY-MM-DD_council-daily_<mode>.md` に書く。Claude の起草が使用量上限で止まったら、欠席扱いにして Python 部分だけ完了させる。
